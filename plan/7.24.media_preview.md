# 7.24 画像プレビュー・動画サムネイル（設計スタブ）

**状態**: `[ ]` 未着手（2026-09-15 起票）
**参考実装**: Zurari（zrr, `../zurari_w`）のプレビュー機構。調査メモは本書 §2。

## 1. 目的

カーソル位置の画像・動画を SideBySide ビューア（4.6）でその場で見る。現状は Text/Hex 表示のみで、
画像は外部ビューア（6.2 / 7.3）を開くしかない。

## 2. zrr の実装から借りるもの（2026-09-15 調査、事実のみ）

- **依存が極小**: 画像デコード用パッケージは無し（WPF 内蔵）。動画は **PATH 上の `ffmpeg` を子プロセスで呼ぶだけ**
  （`src/Zurari.Runtime/VideoThumbnailer.cs`）。無ければ Windows Shell `IThumbnailCache` へフォールバック。
- **ffmpeg 呼び出し**: `-ss 3 -i <path> -frames:v 1 -vf scale=512:-1 -y <tmp.png>`、フレームが出なければ `-ss 0` で再試行。
  全体 20 秒のタイムアウトを 250ms 刻みでポーリングし、キャンセル／タイムアウトでプロセスツリーごと kill。
  Unicode パスは ffmpeg 側（`GetCommandLineW`）が正しく扱う。
- **失敗理由を返す**: `ThumbnailOutcome { Bytes, FailureDetail, Failure: None|FileRejected|Unavailable }`。
  `FileRejected`（ファイル側の問題）はキャッシュし、`Unavailable`（ffmpeg 無し・タイムアウト等＝環境側）はキャッシュしない。
  最終フォールバックは Hex 表示＋理由ラベル（例「ffmpeg が見つかりません(PATH未登録)」）。
- **キャッシュ**: キー = パスの SHA-256 先頭 16 バイト + mtime + サイズ。`%LOCALAPPDATA%\zurari\thumbs`、
  `.png`/`.miss`/`.noshell` の拡張子で種別を区別、tmp→rename の原子的書き込み、30 日超過削除＋ 256MB 上限の LRU 掃除。
- **ジョブモデル**: カーソル移動ごとに世代番号付きの `LoadPreview` を発行し、前世代を `CancelPreview`。
  結果は世代が一致しなければ捨てる（rwf の `active_job_id` 契約と同型）。
- **不採用記録**: ffmpegthumbnailer（Windows の Unicode パス対応フォークが無い）、Shell 優先順（実測で ffmpeg が 6/6 件速かった）。

## 3. rwf 向けの方針案（未決・着手時に詰める）

- **Rust クレート追加ゼロを第一案**: ffmpeg に画像も動画も任せ、PNG ではなく
  `-f rawvideo -pix_fmt rgb24 -s <W>x<H> -` で**生 RGB を stdout へ**出させる → デコーダ不要。
  描画は `rust_console_imgview`（`../rust_console_imgview`）と同じ半ブロック `▄`＋truecolor（1 セル = 上下 2 ピクセル）。
- ジョブ化（`JobKind::RenderPreview` 仮）: 描画パスに FS/プロセス呼び出しを入れない（7.21 の契約テストが守る）。
  カーソル移動で前ジョブを取消、結果はペイン幅×高さ×2 の RGB バッファで `AppState` へ。
- ffmpeg 不在・失敗時は現行の Text/Hex 表示へフォールバックし、理由をビューアのヘッダ行に出す（zrr の `FailureDetail` 相当）。
- 外部プロセス起動は `docs/IMPLICIT_CONTRACTS.md` の規約（直接 spawn、stdout を汚さない）に従う。

## 4. 未決事項
