## Executive Summary

Changes made outside rwf (other apps, shells, sync clients, network peers) never reach a pane
until the user presses F5. Layer 2 closes that gap: the two visible panes of the active tab are
re-read in the background, results that did not change are dropped by the existing comparison,
and results that did change replace the listing **without flashing, without moving the cursor
off its file, and without losing calculated sizes**.

Slow and unreachable drives are handled per drive: the interval backs off, a drive whose poll
listing exceeds a limit is switched off with a notice, and the pane shows `[no poll]` /
`[offline]` so a stale view never looks current. `StopPolling` / `StartPolling` /
`TogglePolling` actions let the user control it from a custom menu.

Polling makes several latent refresh problems constant, so those are fixed first (T0, T1) —
they also improve F5 and post-operation refreshes on their own.

## 2. Decisions

### What is polled, and how

- **D1 — Detection = full background re-read.** Each poll is a ReadDirectory; the existing
  completion comparison discards unchanged listings. twf-style per-file stat is rejected (misses
  added/deleted files); directory-mtime checks are rejected (unreliable on SMB / cloud sync).
  ARCHITECTURE.md Layer 2 text is updated to match (T6).
- **D2 — Panes**: only the two panes of the **active tab**. Background tabs are polled
  immediately when they become active (D17).
- **D3 — Locations**: `Location::Local` only (includes UNC, mapped and removable drives).
  Archive, Ssh, Cloud are never polled.
- **D4 — Pause rules**:
  - A pane with a read already in flight (`active_job_id` set) is skipped.
  - Everything pauses while the terminal is handed to an external command (`SuspendAndRun`)
    and while the **FullScreen** viewer is open.
  - **SideBySide viewer**: only the anchor pane is polled; the hidden pane is treated like a
    background tab and polled when it reappears. The viewer does **not** reload a previewed
    file whose size/mtime changed (live tail is out of scope).
  - Ordinary dialogs do **not** pause polling.
  - **D15**: a pane in range-marking mode or leap mode is not polled (both hold row indices).
    Quick-search and filter typing keep polling.
- **D5 — Mechanism**: the App loop only notices that time has passed and sends
  `Transition::PollTick { now }`. A pure rwf-lib handler selects panes, applies the pause rules
  and per-drive state, and returns `JobSpec`s. No filesystem access in the handler.
- **D6 — Scope**: in: focus-gained poll (D17), the three actions (D10e), indicators (D21),
  diagnostics (D22). Out: 7.13 trash auto-purge piggyback, viewer live reload, per-drive-type
  settings.

### Refresh correctness (applies to every refresh, not only polls)

- **D7 — Cursor stays on its file.** On any ReadDirectory completion that changes the listing,
  restore the cursor by the name it was on, and adjust the scroll offset so the cursor keeps its
  screen row. If that file is gone, keep the old index clamped to the list. An explicit
  `pending_cursor_name` still wins.
- **D8a — Size result logged.** The size-calculation completion line always carries the name
  and the size, e.g. `Calculate size: photos — 12.4 GB [OK]`, even when the job is quiet.
- **D8b — Calculated sizes are carried over and can become "old".** On refresh,
  `calculated_size` is copied onto the new entry with the same `Location`. Each carried value
  remembers the pane's change counter (D12) at calculation time; once the counter has moved
  past it, the size is **stale**.
- **D8c — Stale colour.** New `ColorScheme.StaleSizeForegroundColor` (default `DarkGray`).
  Stale sizes render in it; the cursor row keeps its normal cursor colours.
- **D12 — Pane change counter.** `PaneModel` gets a monotonically increasing counter, bumped by:
  Layer 1 refreshes, the in-memory rename update, and any refresh (including polls) that changed
  the listing. A poll submitted under an older counter value is discarded on completion. This
  stops a poll that read the directory before a rename from reverting it.
- **D13 — Fix the de-duplication bug** (fact table) in 7.5, test first. A stuck `active_job_id`
  would silently disable polling for that pane (D4).
- **D16 — SideBySide preview resync.** Whenever a pane refresh completes in SideBySide mode
  (any origin), run the same preview sync the key path runs, so a deleted previewed file does
  not stay on screen.

### Failures, visibility, timing

- **D9 — Poll read failure.**
  - Directory no longer exists **and its parent is readable** → existing `ResolveFallbackPath`
    behaviour (the folder was deleted; showing that is the point).
  - Anything else (timeout, access denied, share or device unreachable, parent unreadable) →
    silent: no dialog, no navigation. One task-panel line when failures start and one on
    recovery. The drive enters the *failing* state (D21) and backs off (D10b).
- **D11 — Poll jobs are silent.** New `JobOrigin::Poll`: no tab spinner, no 500 ms
  announcement, not listed in `Alt+j`, completion tracing at `debug` level. Failures follow D9.
  A note in `plan/7.22.startup_job_visibility.md` records the exemption (pane stays populated,
  so there is nothing to explain).
- **D10a — Drive key** (pure path parsing where possible):
  - Windows: `C:\` for drive-letter paths (mapped drives keyed by letter, not resolved);
    `\\server\share` for UNC.
  - Linux/macOS: longest-prefix match against the mount table, loaded once by a worker job at
    startup and stored in state; fall back to `/` until it arrives.
- **D10b — Per-drive adaptive interval.**
  - Each drive starts at `PollingIntervalMs`.
  - A poll read taking **> 1 s** (worker-start to finish) or failing doubles the drive's interval.
  - A read ≤ 1 s halves it, never below `PollingIntervalMs`.
  - Ceiling = `max(4000, PollingIntervalMs)`.
  - The next poll of a pane is scheduled from the completion of its previous poll.
  - 1 s and 4 s are constants. `PollingIntervalMs` below 250 is raised to 250; 0 disables polling
    entirely (no ticks, no focus polls, no indicators).
- **D10c — Automatic switch-off.** New top-level `PollingDisableAfterMs` (default 30000,
  0 = never). Measured from **worker start**. Checked on every tick against poll reads still in
  flight, so a hung read trips it without completing. Only poll reads count — a slow manual read
  does not switch a drive off. Scope is the whole drive.
- **D10d — Switch-off notice and lifetime.** One task-panel line per switch-off, e.g.
  `[WARN] Polling stopped for \\srv\share (listing took 31 s) — StartPolling to resume`.
  Session-only (not persisted). F5 still refreshes once but does not restart polling.
- **D10e — Actions.** `StopPolling`, `StartPolling`, `TogglePolling`, acting on the active pane's
  drive. No default key binding; intended for a custom menu (and the command palette later).
  Descriptions in `action_descriptions.en.json` / `.jp.json`.
  - `StartPolling` clears a manual or automatic stop and resets the interval to base.
  - **D18**: `StopPolling` also cancels an in-flight poll on that drive and discards its result.
  - **D18**: on a never-polled location the actions change nothing and log
    `Polling not available for this location`.
  - **D18**: `sample/custom_functions.json` gains a "Polling" submenu with the three actions.
- **D14 — Dedicated poll pool.** `WorkerPoolSize` (default 4) stays for user work; a second,
  fixed **2-worker** pool runs only poll reads (one per visible pane, 6 workers total by default).
  Its events merge into the same event stream. At most one poll per pane is ever queued; a tick
  that finds the poll pool full skips. Hung polls can therefore stall polling, never user
  operations.
- **D17 — Immediate polls.** Terminal focus gained, tab switch, and the SideBySide hidden pane
  reappearing each poll the affected visible panes immediately, bypassing the interval. They
  still skip in-flight panes, stopped drives, and `PollingIntervalMs: 0`. Focus reporting is
  enabled in `terminal.rs` setup, disabled at teardown and around the `SuspendAndRun` handoff in
  `app.rs`; IMPLICIT_CONTRACTS §4 and its guard test are extended to cover it. Terminals that
  never send focus events simply never trigger this.
- **D21 — Indicators** (path line, `WarningColor`, ASCII, width-aware helpers):
  `[no poll]` while the pane's drive is stopped (manually or automatically); `[offline]` while
  its reads keep failing (cleared by the first successful read). Nothing is shown when polling
  is globally off via `PollingIntervalMs: 0`.
- **D22 — Diagnostics.** The F12 state snapshot records, per drive: current interval, state
  (active / stopped-manual / stopped-auto / failing), last poll time. One line in
  `docs/DIAGNOSTIC_BUNDLES.md`.
- **Config reload (`Shift+Z`)**: every drive's current interval resets to the new base; stopped
  drives (manual or automatic) stay stopped.

### New config surface

| Key | Where | Default | Notes |
|---|---|---|---|
| `PollingIntervalMs` | top level (exists) | 1000 | 0 = off; < 250 raised to 250 |
| `PollingDisableAfterMs` | top level (new) | 30000 | 0 = never switch off |
| `StaleSizeForegroundColor` | `ColorScheme` (new) | `DarkGray` | |

## 4. Manual verification checklist

Automated tests cover the pure handler, synthetic timings and temp directories. These need real
hardware; record each run with **F12** and keep the bundle name next to the item.

### Local

- [ ] Create, delete, rename and grow a file from another shell in a visible pane: it appears
      within ~1 s, the cursor stays on its file, marks survive, no flashing.
- [ ] `Alt+s` a folder, then change something in that pane: the size stays and turns
      `StaleSizeForegroundColor`; the task pane shows the size line.
- [ ] Rename in rwf while polling: no one-interval revert.
- [ ] SideBySide: delete the previewed file externally; the preview follows the cursor.
- [ ] Alt-tab away, change a file, return: updated at once (terminal with focus events).

### SMB share

- [ ] Normal share: changes from another machine appear; interval stays at base.
- [ ] Slow listing (large folder): interval backs off to ≤ 4 s; `Alt+j` and the tab bar stay quiet.
- [ ] With `PollingDisableAfterMs: 2000` on a folder that lists slower than 2 s: polling switches
      off, one `[WARN]` line, `[no poll]` shown; `StartPolling` from the custom menu resumes.
- [ ] Disconnect the network: `[offline]` appears, no dialog, pane not navigated away; user
      operations (copy on a local drive) still run. Reconnect: indicator clears, listing updates.

### USB stick

- [ ] Pull the stick while a pane shows it: `[offline]`, no dialog, no navigation, other pane and
      local work unaffected.
- [ ] Re-insert: the pane recovers on the next poll.
- [ ] Delete the shown folder from another shell while the stick is present: the pane falls back
      to the nearest existing ancestor (D9 NotFound path).
