# Phase 4.6: Side-by-Side Viewer Mode

## Context

Currently, the text viewer is full-screen only — opening it replaces the entire UI and hides the file pane. The user wants to be able to browse files in the file pane while viewing text content in a pane on the opposite side, enabling a two-panel workflow. They want:
- **"v"** key: Keep current full-screen viewer behavior
- **"shift+V"** key: Open side-by-side viewer (new feature)
- The viewer should appear opposite to the active file pane (if browsing right pane, viewer goes left; if browsing left pane, viewer goes right)

## Key Constraints

1. **Per-tab state**: Viewer mode (full-screen vs side-by-side) is per-tab only — each tab remembers its own state
2. **Session-based**: On quit, don't persist viewer mode state. On startup, show normal file panes (no side-by-side)
3. **Task pane**: Must NOT be covered by side-by-side viewer — layout should be adjusted to keep task pane visible
4. **Focus navigation**: Tab/Shift+Tab moves focus between file pane and viewer when in side-by-side mode
5. **Mode transitions**: If user opens side-by-side (shift+V), then full-screen (v), then shift+V should return to side-by-side (not toggle back to full-screen)

## Implementation Approach

### 1. Add ViewerMode State
**File: `rwf-lib/src/model/ui.rs` (in PaneModel struct)**

Add per-tab viewer state:
```rust
pub enum ViewerMode {
    FullScreen,      // "v" - full-screen viewer
    SideBySide,      // "shift+V" - viewer opposite to active pane
}

// In PaneModel:
pub viewer_mode: Option<ViewerMode>,      // Current mode (None = no viewer)
pub viewer_preferred_mode: ViewerMode,    // Remember user's preference for shift+V
pub viewer_focus: bool,                   // Whether focus is on viewer (true) or file pane (false)
```

This ensures per-tab state — each tab maintains its own viewer mode preference.

### 2. Add Keybinding for shift+V
**File: `rwf-bin/src/input/mod.rs`**

Modify existing "v" handler and add "shift+V" handler:

**"v" key logic:**
- If viewer not open: open in `viewer_preferred_mode` (defaults to FullScreen)
- If viewer open in SideBySide: switch to FullScreen (and remember SideBySide as preferred)
- If viewer open in FullScreen: close viewer

**"shift+V" key logic:**
- If viewer not open: open in SideBySide mode (and set `viewer_preferred_mode = SideBySide`)
- If viewer open in FullScreen: switch to SideBySide
- If viewer open in SideBySide: close viewer

**Tab/Shift+Tab key logic:**
- If viewer is open and side-by-side: toggle `viewer_focus` between file pane and viewer
- If only file panes: behave normally (switch left/right focus)

### 3. Modify Main Layout Rendering
**File: `rwf-bin/src/ui.rs` (render_ui function, lines 50-68)**

Replace the current logic that returns early for full-screen viewer with conditional rendering:

**If `ViewerMode::FullScreen`**: Keep current behavior (return early, render full-screen viewer only)

**If `ViewerMode::SideBySide`**: 
- Create a 2-part layout: [file_panes_area | viewer_area] (50/50 split)
- Determine which side viewer goes based on active pane from `PaneModel`
- If left pane active: render layout as [file_pane(50%) | viewer(50%)]
- If right pane active: render layout as [viewer(50%) | file_pane(50%)]
- File pane still renders both left/right side-by-side (same as normal, just narrower)
- **Important**: Keep task pane below all other elements (don't cover it)
  - Reduce height available for file panes/viewer layout
  - Reserve space for: metadata lines (path, volume, pane info, filename) + task pane

### 4. Modify Pane Rendering  
**File: `rwf-bin/src/ui/panes.rs`**

When in `SideBySide` mode and viewer is showing:
- Reduce the height available for file panes (take from bottom, before pane info/filename/task lines)
- Still render both left/right panes side-by-side
- Keep all metadata lines (path, volume, pane info, filename)

### 5. Modify Viewer Rendering
**File: `rwf-bin/src/ui/viewer.rs` (render_viewer function)**

The viewer already takes an `area: Rect` parameter, so rendering in a side-by-side area just requires:
- Passing a narrower rect (50% width instead of full width)
- Positioning it on the correct side based on active pane

### 6. State Transitions & Input Handlers

See Section 2 (Keybinding) for detailed transition logic. Key points:

- `viewer_mode` tracks current display mode (FullScreen/SideBySide)
- `viewer_preferred_mode` remembers user's preferred mode for shift+V (persists during session)
- When closing viewer (not opening), always reset `viewer_mode` to None
- When switching modes, preserve the file being viewed
- Tab/Shift+Tab moves focus between panes only when in SideBySide mode with viewer active

## Verification

1. **Initial state**: Open app, should show normal file panes (no viewer)
2. **Press "v"**: Should open file in full-screen viewer
3. **Press "v" again**: Should close viewer, return to file panes
4. **Press "shift+V"**: Should open in side-by-side viewer (opposite to active pane)
5. **In side-by-side mode**:
   - If left pane is active (cursor in left): viewer should appear on right
   - If right pane is active (cursor in right): viewer should appear on left
   - File panes still visible and navigable
   - Task pane not covered
6. **Press Tab/Shift+Tab**: Should move focus between file pane and viewer
7. **Mode transitions**:
   - "shift+V" → full-screen mode → "shift+V": Should return to side-by-side (not toggle)
   - "v" → side-by-side → "v": Should switch to full-screen
8. **On quit and restart**: No viewer should be open (state not persisted)
9. **Tab switching**: Each tab maintains its own viewer state separately
10. Update keybindings in `docs/rwf/keybindings.json`
