## a) twfの実装と機能洗い出し

Explore報告より、twfが備える設定・カスタマイズ機能は以下の通り：

### **設定ファイル体系**

| ファイル | 形式 | 役割 | 主要セクション |
|---------|------|------|----------------|
| `config.json` | JSON | メイン設定 | Display, KeyBindings, FileOperations, Search, UI, Archive, JobManager, TextInput, JumpNav |
| `keybindings.json` | JSON | キーバインディング | NormalMode, SearchMode, DialogMode, ViewerMode, TextViewerBindings, ImageViewerBindings |
| `custom_functions.json` | JSON | カスタム関数 | Name, Command, Shell, WorkingDir, PipeToAction, KeyBinding, OsSpecific |
| `registered_directory.json` | JSON | 登録フォルダ | Name, Path（環境変数展開対応）, Description |

### **twfの主要機能**

**1. 表示設定（Display）**
- 色設定（42個以上）: ForegroundColor, BackgroundColor, ハイライト色、ペイン色、タブ色、ステータス色など
- フォーマット: 日付形式、時間表示（12/24h）、CJK幅（1/2）
- サポートカラー形式: Named colors, Bright variants, RGB hex (#RRGGBB)

**2. キーバインディング（KeyBindings）**
- 62個以上のアクション定義
- カテゴリ: ナビゲーション、ファイル操作、マーキング、検索、表示、タブ、ビューア、その他
- 複数モード対応: Normal, Search, Dialog, Viewer, TextViewer, ImageViewer
- マルチキー対応: Shift+A, Ctrl+Shift+Z など

**3. カスタム関数（CustomFunction）**
- 外部コマンド実行
- マクロ展開: $P, $O, $L, $R, $F, $W, $E, $M, $*, $I, $V, $~, $#, %VAR%, $VAR
- OS別コマンド処理（Windows/Linux/macOS）
- キー割り当て対応
- PipeToAction: JumpToPath, ExecuteFile, ExecuteFileWithEditor

**4. 登録フォルダ（RegisteredFolder）**
- 環境変数展開対応（$HOME, %USERPROFILE%, ${VAR}など）
- UIダイアログで選択実行

**5. ファイルタイプ関連付け（ExtensionAssociations）**
- 拡張子 → 外部ツール自動起動
- 形式不明（twf実装詳細は要確認）

**6. コンテキストメニュー（menu_*.json）**
- 階層化メニュー
- マクロ展開対応

**7. その他設定項目**
- FileOperations: 削除確認、上書き確認、バッファサイズ、タイムスタンプ保持
- Search: 大文字小文字区別、正規表現、Migemo
- UI: リフレッシュレート、スクロールオフセット、タブ幅
- Archive: デフォルト形式、圧縮レベル
- JobManager: 並行ジョブ数、更新間隔、パネル高さ、ログ設定
- TextInput: EmacsモードまたはViモード
- JumpNav: 最大結果数、検索深度

### **ホットリロード**
- キー（Shift+Z相当）で設定の再読み込み（アプリ再起動不要）

## b) 基本方針の定義

### **ユーザー定義の基本方針**

1. **設定ファイルで完結**
   - JSON形式のみ（YAML/TOML等は不要）
   - スクリプト化は避ける
   - GUIエディタより、サンプル・テンプレート・ドキュメント充実

2. **Works Out of the Box**
   - デフォルト値で即座に使用可能
   - 初心者が設定を修正する際の難易度を低く

3. **外部ツール/コマンドラインの柔軟な利用**
   - マクロ展開（$P, $F等）の充実
   - OS別コマンド処理
   - 環境変数対応

4. **Clean, Lean な設計**
   - 不要な機能は追加しない
   - 複雑性を最小化
   - 既存実装の再利用を優先

5. **表示正確性の優先**
   - 外部コマンド実行後は自動リフレッシュ（ユーザー設定なし）
   - 定義漏れ・誤設定のリスク排除（Layer 1設計思想）

## e) 改善案と検討事項

### **1. waitジョブの活用（高優先度）**

**背景**: 外部コマンド実行後のペイン更新（6.1）は、実行完了を正確に知る必要がある。

**案**:
```rust
// JobManager::wait() で実行完了待機
let job_id = job_manager.spawn_external_command("git status", working_dir);
job_manager.wait(job_id)?;  // 完了まで待機
// その後ペイン更新
pane.refresh(ReadDirectory);
```

**メリット**: 同期的にペイン更新でき、表示状態の正確性が保証される
**デメリット**: UI ブロック懸念（解決: 非同期タスクで実装）

---

### **2. 既存機能の再利用（Clean, Lean）**

**実装予定**:
- CustomFunction 実行 → JobManager 経由（既存）
- マクロ展開 → macro_expander 再利用（既存）
- ダイアログ → Dialog系クラス再利用（既存）

**回避すべき**:
- ❌ 新しいジョブ管理機構
- ❌ 新しいマクロ展開エンジン
- ❌ カスタムダイアログフレームワーク

---

### **3. ネーミング一貫性（要確認）**

**現状**:
- アクション: CamelCase (CursorUp, EnterDirectory)
- キーバインディングキー: 混在 (Tab, Ctrl+C, Up/Down)

**twfとの比較**: twf実装詳細確認要

**リスク**: リネーム時のブレークチェンジ（既存ユーザー設定が壊れる）

**対策**: 段階的移行、互換性レイヤー検討

**Clean, Lean理念との矛盾回避**:
- デフォルト値は必ず実装（ユーザーが何も設定しなくても使える）
- 設定ファイルは完全形式を示す（学習・カスタマイズ用）

---

### **6. 設定ファイルのモジュール化（Modular Configuration System）**

**背景**: 現在、色設定は `config.json` の `Display` セクションにフラット化されている。設定が肥大化するとメンテナンス性が低下し、テーマ（配色）の共有や切り替えが困難になる。

**案**:
- **`colors.json` の独立**: 配色設定を独立したファイルに分離する。
- **ファイル体系の整理**:
  - `config.json`: 基本動作設定（検索、UI動作、ファイル操作等）
  - `keybindings.json`: キーバインド
  - `colors.json`: 配色（新規）
  - `custom_functions.json`: カスタム関数
  - `registered_folders.json`: 登録フォルダ
- **メリット**:
  - ユーザーがテーマファイル（`colors.json`）を差し替えるだけで外観を簡単に変更できる。
  - 設定ファイルごとの責務が明確になり、パースエラー時の影響範囲を限定できる。
  - `ConfigManager` がこれらのファイルを一括、またはオンデマンドで管理する。

---

### **7. 設定管理クラス（ConfigManager）の洗練**

**案**:
- **マルチファイル・ローダー**: 複数の JSON ファイルを非同期・並列に読み込み、一つの `AppConfig` 相当の状態に統合する。
- **フォールバック機構**: `colors.json` 等が存在しない場合、デフォルト値または `config.json` 内の古い形式（互換性維持のため）から読み込む。
- **ホットリロードの強化**: ファイルごとの監視（Phase 7 のポーリング等）により、ファイルが手動で編集された際に自動で反映する。
