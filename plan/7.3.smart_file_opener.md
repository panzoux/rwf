# Phase 7.3 — スマート・ファイルオープナー（Rifle + コンテンツ判定）

**作成日**: 2026-07-18
**状態**: 仕様確定
**対象**: 「このファイル、何で開けばいい？」を一元的に解決する。旧 7.3 Rifle System と
旧 8.7（Future Enhancement Candidates のマジックバイト判定）を統合したもの。

---

## 1. 目的・背景

`ExtensionAssociation`（Phase 6.2）と `file_type_map.json` は「拡張子」だけを見て開き方を決める。
これは大半のケースで十分だが、以下の2点が未解決だった。

1. **複数候補**: 同じ拡張子を複数のツールで開きたい場合（例: `.jpg` を画像ビューアでも
   エディタでも開けるようにする）、選択する手段がない。
2. **拡張子とファイル実体の不一致**: 拡張子は文書だが実体は実行ファイル、といったケースを
   検知できない。`ExtensionAssociation.description` の隣にある `FileTypeMapping.file_type`
   （MIME-ish 文字列）はこの用途のために予約されていたが未使用のまま放置されていた。

本フェーズはこの2点を、既存の3つの開き方（`Enter` / `Ctrl+Enter` / コンテキストメニュー）の
どれも壊さずに追加する。

### 非目標（将来の Phase 8+ へ送る）

- libmagic 連携（`magic` クレート）: Windows に標準で無く、クロスプラットフォーム方針に反するため不採用。
- ユーザー定義のマジックバイト表（`file_type_map.json` と同じパターンでの拡張）: 手組みの
  内蔵テーブルでカバーしきれない形式が出てきた時点で検討。
- ファイル一覧ペインへの常時表示（アイコン/列）: スクロール中の常時 I/O コストを避けるため、
  File Information ダイアログでのオンデマンド表示に留める。

---

## 2. 既存の開き方（変更なし）

| キー | 現在の挙動 | 実装 |
|---|---|---|
| `Enter` | `ExtensionAssociation` 先頭一致 → `FileTypeMapping` → 内蔵テキストビューア | `input/mod.rs:772-881` |
| `Ctrl+Enter` | OS標準の関連付けで開く（`start`/`open`/`xdg-open`） | `Transition::OpenWithSystem` → `state/helpers.rs` `system_open_job()` |

この2つは「即座に確実に開く」ためのパスとして維持する。特に `Ctrl+Enter` は
「OSに判断を委ねる」明示的な抜け道であるため、不一致警告の対象にしない。

---

## 3. 新規: 「Open With...」ピッカー

- コンテキストメニュー（`` ` ``、Phase 6.4）に新規デフォルトアクション `OpenWith...` を追加。
- `ExtensionAssociation` の**スキーマは変更しない**（既に `Vec<ExtensionAssociation>` なので、
  同じ拡張子のエントリを複数書けば「候補リスト」になる）。ディスパッチ側だけを変更:
  - 一致0件 → 4章のコンテンツ判定へフォールスルー
  - 一致1件 → そのまま実行（ピッカーを出さない）
  - 一致2件以上 → ピッカー表示
- ピッカーの UI は新規ダイアログ型を作らず、`CustomFunctionMenu`（Phase 6.6）/ `ContextMenu`
  （Phase 6.4）と同じ選択リストパターンを再利用する。

### 複数選択（マーク済みファイル）を Open With する場合

1. マーク済み各ファイルに対し header 読み取り（4章のジョブ）をバッチ実行。
2. 検出タイプ（4章）でグルーピング。
3. グループごとに候補が1件なら即実行、複数ならグループごとにピッカーを表示。
4. 実行時は同グループの全パスをコマンド引数として渡す（マクロ展開は既存 `MacroExpander` を
   複数パス対応で使う）。

## 4. コンテンツ判定（マジックバイト検出）

### モジュール

`rwf-lib/src/magic.rs`（新規）。手組みの静的シグネチャテーブル。libmagic 非依存。

対象は「実用上よく遭遇し、かつ判別に価値がある」形式に絞る。優先度が高いのは
**拡張子詐称の検知**（文書拡張子で実行ファイル実体）なので、実行ファイル系は必須。

- 画像: PNG, JPEG, GIF, BMP, WEBP
- アーカイブ: ZIP, GZIP, 7Z（Phase 5 のハンドラとは独立した「見た目の判定」であり、
  アーカイブとして開けるかどうかとは別の関心事）
- 文書: PDF
- 実行ファイル: PE (`MZ`), ELF, Mach-O ← 拡張子との不一致が最も実害のあるケース
- 上記いずれにも一致しない場合は `DetectedKind::Unknown`（判定不能。警告もフォールバックもしない）

先頭 ~300 バイト読み取りで足りる（`infer` クレート等の慣例に合わせる）。

### ジョブ化（アーキテクチャ必須）

CLAUDE.md の原則「UI スレッドで副作用を起こさない、I/O は全て Job」に従い、
ネットワークドライブでの読み取り遅延を考慮して**必ず非同期ジョブ**として実行する。

- `JobKind::DetectFileType { path }` — 単一ファイル（不一致チェック・File Info オンデマンド共用）
- `JobKind::DetectFileTypesBatch { paths }` — 複数マーク済みファイル一括（Open With グルーピング用）

既存の `SeekableFile`（Phase 6.6 LargeFileEngine）のチャンク読みインフラを再利用し、
mmap 等の新規依存は追加しない。

### 設定

`config.json` に `magic_byte_detection_enabled: bool`（デフォルト `true`。数百バイトの
読み取りのみで軽量なため、デフォルト有効とする）。

セッション限定の一時トグルとして未使用の `y` プレフィックスを使い `y+m` に割り当てる
（キー自体は実装時の微調整余地あり）。config ファイルは書き換えず、実行中のみ config 値を
上書きするインメモリフラグとして持つ。

## 5. 不一致警告

- `Enter` またはピッカー経由でコマンドを実行する**直前**に検出ジョブを挟む。
- 検出結果が `FileTypeMapping.file_type`（またはピッカーで選んだ `ExtensionAssociation` が
  暗黙に想定する種別）と食い違い、かつ `magic_byte_detection_enabled` が有効な場合、
  新規ダイアログ `DialogContent::TypeMismatchWarning { path, declared, detected }` を表示。
  - Confirm: 保留中のコマンドをそのまま実行
  - Cancel: 何もせず閉じる
- レンダリングは `rwf-bin/src/ui/dialog/common.rs` のスタイル定数・`titled_block` と
  `frame.rs` の `render_dialog_frame`/`render_dialog_buttons` を使用（新規のインライン
  `Style::default()` チェーンを書かない、既存の Dialog 規約に従う）。
- `Ctrl+Enter`（OS標準open）はこのチェックを通さない（2章参照）。

## 6. 拡張子未登録ファイルのフォールバック強化

現状: `ExtensionAssociation` にも `FileTypeMapping` にも一致しない拡張子は、無条件に
内蔵テキストビューアへ渡っている（バイナリをテキストとして開いてしまう）。

変更後: 4章の検出ジョブを1回走らせ、既知の非テキスト種別（PNG 等）が検出されたら
`Transition::OpenWithSystem` へルーティング。`Unknown` の場合のみ、従来通りテキスト
ビューアへフォールスルーする（挙動は変えない）。

---

## 7. File Information ダイアログでの表示

- 既存の `i`（`ShowFileInfoForCursor`）は変更しない。ダイアログを開いた時点では
  検出を自動実行しない（閲覧・比較目的での連打時に不要な I/O を発生させないため）。
- ダイアログ内でキー入力によりオンデマンドで `JobKind::DetectFileType` を発行し、
  結果を「Detected type: PNG image」のような行として追記表示する。不一致の場合は
  「(mismatch — extension implies .txt)」を添える。

---

## 8. ログ / 履歴

新規の永続化機構は追加しない。既存のタスクパネル（`task_panel.add_log`、Phase 1.10 で
確立済みのログ出力方式）にそのまま乗せる。

- 不一致警告が出た場合: `[Warning] Type mismatch: notes.txt looks like PE executable (declared: text/plain)`
- 通常の検出（File Info でのオンデマンド等）: `[System] Detected type: PNG image for photo.jpg`

タスクパネルのログは既存の仕組みでセッションログファイルへも出力されるため、
「後から履歴を確認したい」という要求はこれで満たされる。

---

## 9. テスト方針

- `magic.rs` 単体テスト: 各シグネチャのフィクスチャバイト列で判定を検証（テーブル駆動）。
- `file_open_integration_tests.rs` への追加: 不一致警告の表示/確認/キャンセル分岐、
  拡張子未登録ファイルのフォールバック強化（PNG 検出 → OsDefault ルーティング）、
  複数候補時のピッカー構築（0/1/2+件の分岐）。
- ダイアログスナップショットテスト: `TypeMismatchWarning` と Open With ピッカーのレンダリング
  （既存の insta スナップショット網羅パターンに準拠）。
- ネットワークドライブ相当の遅延ケースは既存の Job キャンセル/タイムアウトパターンを踏襲。

---

## 10. 制限事項

- 内蔵テーブルは網羅的な `file` コマンド相当ではない。未知形式は素通し（誤検知よりは
  無警告を優先する設計）。
- アーカイブ系シグネチャ（ZIP/7Z等）は Phase 5 のアーカイブハンドラと判定ロジックが
  重複するが、意図的に独立させる（「アーカイブとして展開できるか」と「見た目のタイプ」は
  別の関心事のため）。
- バッチ Open With のグルーピングはヘッダ読み取りのジョブコストに比例するため、
  極端に大量のファイルを一度にマークした場合の体感速度は要検証（実装時に上限や
  プログレス表示の要否を判断）。
