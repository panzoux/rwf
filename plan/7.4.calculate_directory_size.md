# Phase 7.4 — Background Directory Size Calculation

**Created**: 2026-06-04  
**Status**: Design Document  
**Priority**: Phase 7 (Post-TWF Parity Enhancement)

---

## Executive Summary

Add explicit, non-blocking directory size calculation via **Shift+S** keybinding. Job spawns as background task, fills pane sizes incrementally, shows progress in task pane. **Critical design choice**: Cancel job when user navigates away from source pane (explicit control, respects user intent).

**Deliverable**: Recursive size calculation for all visible entries in current pane, with spinner feedback and task pane audit trail.

---

## Use Case

```
User in /home/user:
  Documents/  (d)
  Downloads/  (d)
  Pictures/   (d)

User: Shift+S
  ↓ Spinner appears on tab
  ↓ Task pane: "[SizeCalc] Scanning Documents... (45 dirs, 234 files)"
  ↓ Documents/ now shows "15.6 GB" (incremental update)
  ↓ Task pane: "Documents: 15.6 GB"
  ↓ User can switch tabs, create new panes, continue work
  ↓ Returns to original tab: all sizes filled in
  ↓ Task pane: "✓ SizeCalc complete: 3 entries, 127.4 GB total (as of 14:32:15)"
```

Action::CalculateDirectorySizes => {
    let location = state.get_active_pane().location.clone();
    let pane_id = state.active_pane_id();
    
    let job = JobSpec::new(JobKind::CalculateDirectorySizes {

        pane_id,

### Job Executor Logic

```rust
// job/job_executor.rs
JobKind::CalculateDirectorySizes { location, pane_id, initiated_at } => {
    execute_calculate_directory_sizes(
        location,
        pane_id,
        initiated_at,
        &cancel_token,
        &tx,
    ).await
}

async fn execute_calculate_directory_sizes(
    location: Location,
    pane_id: usize,
    initiated_at: SystemTime,
    cancel_token: &CancellationToken,
    tx: &JobOutputChannel,
) -> Result<()> {
    let mut total_size = 0u64;
    let mut entry_count = 0usize;
    let mut file_count = 0u64;
    
    // Read directory entries
    let entries = read_directory(&location).await?;
    
    for entry in entries {
        if cancel_token.is_cancelled() {
            tx.log_message("[SizeCalc] Cancelled by user");
            return Ok(());
        }
        
        if entry.is_dir {
            // Start scanning message
            let display_name = entry.name.clone();
            tx.log_message(format!(
                "[SizeCalc] Scanning: {}... ({} items estimated)",
                display_name,
                estimate_dir_items(&entry.location)?
            ));
            
            // Calculate size (with progress callback)
            let start = Instant::now();
            let dir_size = calculate_dir_size_recursive(
                &entry.location,
                cancel_token,
                |_sub_path, _item_count| {
                    // Could emit granular progress if needed
                    // But keep task pane updates at "per-directory" level
                }
            ).await?;
            
            let elapsed = start.elapsed();
            total_size += dir_size;
            entry_count += 1;
            
            // Emit UI update: fill in this entry's size
            tx.emit(JobOutput::UpdateFileSize {
                pane_id,
                path: entry.location.clone(),
                size: dir_size,
            })?;
            
            // Task pane: completion for this directory
            tx.log_message(format!(
                "[SizeCalc] {}: {} (calculated in {:.1}s)",
                display_name,
                format_bytes(dir_size),
                elapsed.as_secs_f64()
            ));
            
            // Yield to UI thread (allow pane updates)
            tokio::time::sleep(Duration::from_millis(5)).await;
        }
    }
    
    // Final completion message
    let elapsed = SystemTime::now()
        .duration_since(initiated_at)
        .unwrap_or_default();
    
    let timestamp = chrono::Local::now().format("%H:%M:%S").to_string();
    
    tx.log_message(format!(
        "[SizeCalc] ✓ Complete: {} entries, {} total (as of {}, {:.1}s elapsed)",
        entry_count,
        format_bytes(total_size),
        timestamp,
        elapsed.as_secs_f64()
    ));
    
    Ok(())
}

/// Recursively calculate directory size, respecting symlink policy
async fn calculate_dir_size_recursive(
    location: &Location,
    cancel_token: &CancellationToken,
    visited: &mut HashSet<FileId>,  // Windows: file ID; Unix: inode
) -> Result<u64> {
    let mut total = 0u64;
    
    let entries = read_directory(location).await?;
    
    for entry in entries {
        if cancel_token.is_cancelled() {
            return Err(anyhow::anyhow!("Cancelled"));
        }
        
        // Skip symlinks by default (config option to follow)
        if entry.is_symlink && !config.follow_symlinks_in_size_calc {
            continue;
        }
        
        // Prevent circular reference via inode/file ID
        if entry.is_dir {
            let file_id = get_file_id(&entry.location)?;
            if visited.contains(&file_id) {
                continue;  // Already visited, skip
            }
            visited.insert(file_id);
            
            total += calculate_dir_size_recursive(
                &entry.location,
                cancel_token,
                visited
            ).await?;
        } else {
            total += entry.size;
        }
    }
    
    Ok(total)
}
```

### State Transition

```rust
// state.rs
pub enum Transition {
    // ... existing ...
    
    /// Update a single file's cached size in pane
    UpdateFileSize { pane_id: usize, path: PathBuf, size: u64 },
    
    /// Mark size calculation complete for pane
    SizeCalculationComplete { pane_id: usize },
}

impl Transition {
    pub fn apply(self, state: &mut AppState) -> Result<()> {
        match self {
            Transition::UpdateFileSize { pane_id, path, size } => {
                if let Some(pane) = state.get_pane_mut(pane_id) {
                    pane.size_cache.insert(path, size);
                }
                Ok(())
            }
            Transition::SizeCalculationComplete { pane_id } => {
                if let Some(pane) = state.get_pane_mut(pane_id) {
                    pane.size_calc_in_progress = false;
                    pane.current_size_calc_location = None;
                }
                Ok(())
            }
            // ... other transitions ...
        }
    }
}
```

## Edge Cases & Solutions

### 1. User Navigates Away During Calculation

**Design Decision**: **CANCEL job immediately.**

**Rationale**:
- User may intentionally want to calculate a different directory
- No clean UI to cancel job (other than Job Manager dialog, which is modal)
- Implicit "keep running" frustrates users (wastes CPU, unclear job ownership)
- Explicit cancellation is easier to understand

**Implementation**:

```rust
// When user changes location in pane
Transition::ChangeLocation { pane_id, location } => {
    if let Some(pane) = state.get_pane_mut(pane_id) {
        // Cancel any in-flight size calculation for this pane
        if let Some(job_id) = pane.active_size_calc_job {
            state.job_manager.cancel(job_id);
        }
        pane.size_calc_in_progress = false;
        pane.current_size_calc_location = None;
        pane.location = location;
    }
    Ok(())
}
```

**User Experience**:
```
/home/user: [Shift+S] → Spinner on tab, calculating sizes
  ↓ (2 seconds later)
User: Press 'j' or 'k' to move cursor → no effect on calculation
User: Press Enter on /tmp → ChangeLocation triggered
  ↓
Job cancelled, spinner stops
Task pane: "[SizeCalc] Cancelled (user navigated to /tmp)"
New pane shows /tmp, ready for independent calculation
Original pane (/home/user) retains partial size_cache (nice for back-navigation)
```

### 2. File Added/Deleted During Calculation

**Design**: Accept snapshot semantics. Show timestamp explicitly.

**Message Format**:
```
[SizeCalc] ✓ Complete: 847 files, 127.4 GB total (as of 14:32:15)
```

**Rationale**:
- Recursive scan takes time; file system may change during scan
- Attempting to "lock" directory or re-scan is too expensive
- Users understand "snapshot at time T" semantics (familiar from `du`, `ncdu`)

**Implementation**:
```rust
let timestamp = chrono::Local::now().format("%H:%M:%S").to_string();
tx.log_message(format!(
    "[SizeCalc] ✓ Complete: ... (as of {})",
    timestamp
));
```

### 3. Symlinks & Circular References

**Design Decision**: Three-part approach:

#### a) **File ID-Based Cycle Detection** (Safe Default)

Use platform-specific file identifiers:
- **Windows**: `GetFileInformationByHandle() → nFileIndexHigh/Low`
- **Unix**: `stat() → st_ino` (inode)
- **macOS**: `stat() → st_ino`

```rust
#[cfg(windows)]
fn get_file_id(path: &Path) -> Result<u64> {
    use winapi::um::fileapi::GetFileInformationByHandle;
    // ... implementation ...
}

#[cfg(unix)]
fn get_file_id(path: &Path) -> Result<u64> {
    let stat = std::fs::metadata(path)?;
    Ok(stat.ino())
}
```

**Limitation**: Cannot cross filesystem boundaries reliably on all platforms, so approach is conservative.

#### b) **Symlink Following Policy** (Configurable)

```rust
// config.rs
pub struct SizeCalculationConfig {
    /// Follow symbolic links during size calculation (default: false)
    pub follow_symlinks: bool,
}

// Then in job executor:
if entry.is_symlink && !config.follow_symlinks {
    continue;  // Skip symlinks
}
```

#### c) **Default Behavior**: No Symlink Following

```rust
// Default: config.follow_symlinks = false
// Prevents:
// - Symlink loops (A -> B -> A)
// - Counting the same files twice
// - Slow network symlinks
```

**Why conservative default?**
- Matches behavior of `du` (standard Unix tool)
- Users understand "directories only"
- No surprising slowness
- Can enable via config if needed

**Config Option**:
```json
{
  "size_calculation": {
    "follow_symlinks": false,
    "max_depth": null,
    "timeout_secs": 300
  }
}
```

### 4. Network Drives (Slow Calculation)

**Problem**: User needs to cancel long-running job.

**Current Options**:
- Ctrl+C (global?) — unclear which job
- Job Manager dialog (modal, disrupts workflow)

**Solution for Now**: Use **Job Manager Dialog** (Shift+J)
- Shows all running jobs
- User clicks "X" next to CalculateDirectorySizes job
- Job cancels, task pane updates

**Better UX (Future)**:
- Escape key while task pane visible → cancel job?
- Right-click on task pane log → cancel?
- (Deferred to Phase 7.5+)

**For This Phase**: Document in help:
```
[Help] To cancel size calculation:
  • Press Shift+J to open Job Manager
  • Select CalculateDirectorySizes job
  • Press X or Delete to cancel
```

**Task Pane Visibility**: Keep task pane visible by default during size calc (user can see progress).

---

### 5. Large Directories (10M+ Files)

**Problem**: Task pane updates every file → floods pane, poor UX.

**Solution**: Batch task pane updates.

```rust
// In job executor
const LOG_BATCH_SIZE: usize = 100;  // Update task pane every 100 dirs
let mut batch_count = 0;

for entry in entries {
    // ... calculate size ...
    
    batch_count += 1;
    if batch_count >= LOG_BATCH_SIZE {
        tx.log_message(format!(
            "[SizeCalc] Progress: {} entries processed...",
            entry_count
        ));
        batch_count = 0;
    }
}
```

**Task Pane Messages**:
```
[SizeCalc] Started: /huge/directory
[SizeCalc] Progress: 100 entries processed...
[SizeCalc] Progress: 200 entries processed...
[SizeCalc] Progress: 300 entries processed...
[SizeCalc] Documents: 48.3 GB
[SizeCalc] Downloads: 127.4 GB
[SizeCalc] ✓ Complete: 1,000,000 entries, 2.3 TB total
```

**File Pane Rendering**: Already batched (UI updates only on `Transition::UpdateFileSize`, which happens per-directory, not per-file).

## Risk Assessment

| Risk | Severity | Mitigation |
|------|----------|-----------|
| Symlink loops cause infinite hang | **High** | File ID tracking (visited_inodes) + config option |
| Network drive timeout (slow NFS) | **Medium** | Task pane shows progress; user can cancel via Job Manager |
| File system changes during scan | **Low** | Document snapshot semantics; show timestamp |
| Task pane spam (10M files) | **Medium** | Batch updates every 100 dirs |
| User forgets job is running | **Low** | Spinner on tab bar (always visible) |

**Key design decision**: Cancel job when user navigates away (explicit, respects intent).

**User benefit**: Understand disk usage without switching to `du`/`ncdu` + back.
