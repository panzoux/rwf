## 主な修正点（この版）

1. **メニュー呼び出しの流れを明確化**: Key → CustomFunction（Menu フィールド）→ menu_*.json
2. **外部コマンド実行**: ExecutionMode パラメータ + オプショナル LockPane 機能
3. **GUI/TUI の区別**: 名前では判定不可 → 明示的パラメータで指定

5. **Shell 指定**: 関数ごとに使用シェルを指定可能
6. **環境変数展開**: `$env:VAR` (PowerShell) 対応を追加
7. **ペイン ロック** メカニズム: Terminal Ownership, Output Capture, Layer 1 Refresh の3つの理由

## 3. 設定リロード互換性マトリックス

### **リロード可能 vs 再起動必須**

設定のホットリロード（Shift+Z）を適用する際、すべての設定が再読み込み可能ではありません。以下の区分に従う:

#### **🔴 再起動必須（アプリケーション再起動後に適用）**

| 設定項目 | ファイル | 理由 |
|----------|---------|------|
| `LogLevel`, `LogFilePath` | config.json | ログシステムのランタイム初期化に依存 |
| `MaxConcurrentJobs`, `JobQueueSize` | config.json | ジョブキュー の既存状態を変更すると競合条件 |
| `DefaultCompressionFormat` | config.json | ランタイム中のアーカイブ操作に影響 |

**実装時の注意:**
- ユーザーが Shift+Z を押してもこれらの設定は変更されない
- ログに警告を出す: "LogLevel requires app restart to take effect"

#### **🟢 ホットリロード対応（Shift+Z で即座に適用）**

| 設定項目 | ファイル | 理由 |
|----------|---------|------|
| Colors (全て) | colors.json | UI 描画のみ、ペイン状態に影響なし |
| KeyBindings (全て) | keybindings.json | 入力バインディング、古い値は即座に置換 |
| DateFormat, TimeFormat | config.json | 次回の描画時に適用 |
| TabWidth, ScrollOffset | config.json | UI レイアウト、次回の描画時に適用 |
| CaseSensitiveSearch, UseRegex | config.json | 新規検索時に適用、既存検索は影響なし |
| CustomFunctions (全て) | custom_functions.json | オンデマンド実行時に新定義を読み込み |
| RegisteredFolders (全て) | registered_folders.json | ダイアログ開く際に新リストを表示 |
| ContextMenu (全て) | context_menu.json | メニュー表示時に新リストを表示 |

**実装時の注意:**
- 各セクションの ConfigManager を `reload_configuration()` で呼び出す
- UI は再描画（pane.refresh() 呼び出し）
- 既存のセッション状態（マーク、検索入力）は保持

## 4. カラーシステム（3段階対応）

### **色定義システム: 16色 → 256色 → RGB への段階的対応**

rwf はデフォルトで "works out of the box" を実現するため、複数の色定義レベルをサポート:

#### **Level 1: 名前付き色（16色、推奨デフォルト）**

ターミナルの基本色。確実に全環境で動作:

```json
{
  "colors": {
    "foreground": "White",
    "background": "Black",
    "highlight": "LightYellow",
    "cursor": "LightCyan",
    "directory": "LightBlue",
    "marked_file": "LightGreen",
    "error": "LightRed"
  }
}
```

**サポート名:**
- 基本 8 色: `Black`, `Red`, `Green`, `Yellow`, `Blue`, `Magenta`, `Cyan`, `White`
- 明るい 8 色: `LightRed`/`BrightRed`, `LightGreen`/`BrightGreen`, `LightYellow`/`BrightYellow`, `LightBlue`/`BrightBlue`, `LightMagenta`/`BrightMagenta`, `LightCyan`/`BrightCyan`
- グレースケール: `Gray`/`Grey`, `DarkGray`/`DarkGrey`

**現在の rwf サポート:** ✅ Level 1 のみ (rwf-bin/src/ui/colors.rs)

#### **Level 2: 256 色（インデックスベース）**

高度な色カスタマイズが必要なユーザー向け:

```json
{
  "colors": {
    "foreground": "231",  // White (256-color index)
    "background": "16",   // Black
    "highlight": "226",   // Bright yellow
    "directory": "33",    // Blue
    "marked_file": "46"   // Bright green
  }
}
```

**利点:**
- より多くの色選択肢（256種類）
- 独自のカラースキーム作成可能

**実装:**
```rust
fn parse_color(color_str: &str) -> Color {
    // 256 色インデックスをチェック（0-255 の数値）
    if let Ok(index) = color_str.parse::<u8>() {
        if index < 256 {
            return Color::Indexed(index);
        }
    }
    // ... 既存のロジック（名前、RGB）
}
```

#### **Level 3: RGB（24ビット色）**

最高品質の色カスタマイズ。最新ターミナルで対応:

```json
{
  "colors": {
    "foreground": "#FFFFFF",    // RGB White
    "background": "#000000",    // RGB Black
    "highlight": "#FFFF00",     // RGB Yellow
    "directory": "#0000FF",     // RGB Blue
    "marked_file": "#00FF00"    // RGB Green
  }
}
```

**利点:**
- 完全なカラーカスタマイズ（1600 万色）
- 独自ブランドカラーを正確に表現可能

**注意:**
- 古いターミナルで動作しない場合、最も近い 16 色または 256 色に fallback（ターミナルライブラリが自動処理）

**実装:**
```rust
fn parse_color(color_str: &str) -> Color {
    // RGB hex をチェック
    if color_str.starts_with('#') && color_str.len() == 7 {
        if let Ok(rgb) = u32::from_str_radix(&color_str[1..], 16) {
            let r = ((rgb >> 16) & 0xFF) as u8;
            let g = ((rgb >> 8) & 0xFF) as u8;
            let b = (rgb & 0xFF) as u8;
            return Color::Rgb(r, g, b);
        }
    }
    // ... 256 色、名前付き色のチェック
}
```

#### **parse_color() 実装の完全な優先順位**

```rust
pub fn parse_color(color_str: &str) -> Color {
    let trimmed = color_str.trim();
    
    // 1. RGB hex (#RRGGBB) をチェック
    if trimmed.starts_with('#') && trimmed.len() == 7 {
        if let Ok(rgb) = u32::from_str_radix(&trimmed[1..], 16) {
            let r = ((rgb >> 16) & 0xFF) as u8;
            let g = ((rgb >> 8) & 0xFF) as u8;
            let b = (rgb & 0xFF) as u8;
            return Color::Rgb(r, g, b);
        }
    }
    
    // 2. インデックス（0-255）をチェック
    if let Ok(index) = trimmed.parse::<u8>() {
        if index < 256 {
            return Color::Indexed(index);
        }
    }
    
    // 3. 名前付き色（大文字小文字区別なし）をチェック
    match trimmed.to_lowercase().as_str() {
        "black" => Color::Black,
        "red" => Color::Red,
        "green" => Color::Green,
        "yellow" => Color::Yellow,
        "blue" => Color::Blue,
        "magenta" => Color::Magenta,
        "cyan" => Color::Cyan,
        "gray" | "grey" => Color::Gray,
        "darkgray" | "darkgrey" => Color::DarkGray,
        "lightred" | "brightred" => Color::LightRed,
        "lightgreen" | "brightgreen" => Color::LightGreen,
        "lightyellow" | "brightyellow" => Color::LightYellow,
        "lightblue" | "brightblue" => Color::LightBlue,
        "lightmagenta" | "brightmagenta" => Color::LightMagenta,
        "lightcyan" | "brightcyan" => Color::LightCyan,
        "white" => Color::White,
        _ => Color::White, // デフォルト fallback
    }
}
```

#### **Config 例（複合使用）**

```json
{
  "version": "1.0",
  "colors": {
    "foreground": "#E0E0E0",        // RGB（最新ターミナル向け）
    "background": "Black",          // 名前付き色（後方互換性）
    "highlight": "226",             // 256 色インデックス
    "selected": "LightCyan",        // 名前付き色
    "marked": "#00FF00",            // RGB
    "directory": "33",              // 256 色
    "error": "LightRed",            // 名前付き色
    "warning": "226"                // 256 色
  }
}
```

**推奨:**
- **デフォルト設定** (config.json): 名前付き色のみ使用（最大互換性）
- **カスタム設定** (colors.json): ユーザーが任意に選択可能

## 5. アクション命名規則（決定）

### **命名規則: CamelCase で統一**

```
✅ EditConfigFile, ReloadConfiguration, OpenConfigDirectory
✅ CopyToOtherPane, DeleteFile, OpenCommandPrompt, ViewFileAsText
❌ edit config file, copy_to_other_pane, open-command-prompt (避ける)
```

**理由:**
- Rust struct/enum 命名規則に統一（rwf の慣例）
- JSON キーは大文字小文字区別 → ユーザー入力エラーを削減
- rwf 既存の62個アクション（CursorUp, EnterDirectory 等）と整合

**後方互換性:**
- パーサが古い形式（スペース/snake_case）を新 CamelCase にマッピング
- 1 リリースサイクル間、ログに deprecation warning を出す

## 6. ユーザーインターフェース

### **6a. メニューシステムと呼び出し流れ**

#### **呼び出しフロー（実装例）**

```
キー "Z" (keybindings.json)
  ↓
CustomFunction "menu_config" を検索 (custom_functions.json)
  ↓
CustomFunction が "Menu": "menu_config.json" を指す
  ↓
menu_config.json を表示（ユーザーが選択）
  ↓
選択されたアクションを実行
```

#### **CustomFunction の構造（2 つのタイプ）**

**タイプ 1: メニューベース（選択ダイアログを表示）**

```json
{
  "Name": "menu_config",
  "Menu": "menu_config.json",
  "Description": "Show configuration menu"
}
```

実行時: menu_config.json のアイテムを表示 → ユーザー選択 → Action 実行

**タイプ 2: コマンドベース（コマンド実行）**

```json
{
  "Name": "Open in Notepad",
  "Command": "notepad \"$P\\$F\"",
  "Description": "Open current file in Notepad",
  "Shell": "cmd.exe",
  "ExecutionMode": "GUI",
  "LockPane": false,
  "PipeToAction": null
}
```

フィールド詳細:
- `Command`: 実行するコマンド（マクロ展開対応）
- `Shell`: (オプション) 使用シェル (cmd.exe, powershell.exe, /bin/bash など)
- `ExecutionMode`: "GUI" または "TUI" (デフォルト: "GUI")
- `LockPane`: true/false — ペイン ロック するか (デフォルト: false、TUI は常に true)
- `PipeToAction`: (オプション) 出力をどのアクションにパイプするか

#### **メニューファイル構造** (例: menu_config.json)

```json
{
  "Version": "1.0",
  "Menus": [
    {
      "Name": "Edit Config (config.json)",
      "Action": "EditConfigFile",
      "Params": { "filename": "config.json" }
    },
    {
      "Name": "Edit Keybindings (keybindings.json)",
      "Action": "EditConfigFile",
      "Params": { "filename": "keybindings.json" }
    },
    {
      "Name": "Edit Custom Functions (custom_functions.json)",
      "Action": "EditConfigFile",
      "Params": { "filename": "custom_functions.json" }
    },
    {
      "Name": "-----",
      "Action": ""
    },
    {
      "Name": "Reload Configuration (Shift+Z)",
      "Action": "ReloadConfiguration"
    },
    {
      "Name": "Open Config Directory",
      "Action": "OpenConfigDirectory"
    }
  ]
}
```

**メモ:**
- セパレータ: `"-----"` (ASCII、入力が簡単) または `"─────"` (Unicode) 両対応
- 研究知見: 5 回の繰り返しは他の意図と知覚的に区別可能

#### **EditConfigFile アクション実装（疑似コード）**

```rust
pub fn execute_action(action: &str, params: Option<Map>) -> Result<()> {

                "colors.json" => reload_colors()?,
                _ => return Err(format!("Unknown config: {}", filename)),
            }
            
            Ok(())
        },
        // ... その他アクション
    }
}
```

### **6b. 外部コマンド実行戦略**

#### **課題: 名前だけでは GUI/TUI を区別できない**

例:
```
"vim $F"          → TUI（ターミナル制御が必要）
"notepad $F"      → GUI（ウィンドウ開く、すぐ制御返却）
"git diff"        → パイプ出力か対話的か判定不可
"cmd /k cd ."     → TUI（/k でウィンドウ開いたまま）
"cmd /c copy"     → 高速操作（完了早い、自動リフレッシュ）
```

**解決策: 明示的な ExecutionMode パラメータ + オプショナル LockPane**

```json
{
  "Name": "Open in Notepad (non-blocking)",
  "Command": "notepad \"$P\\$F\"",
  "ExecutionMode": "GUI",
  "LockPane": false,
  "Description": "ファイルを Notepad で開く（ロック無し）"
}
```

```json
{
  "Name": "Edit config (wait for save)",
  "Command": "notepad \"$env:APPDATA\\rwf\\config.json\"",
  "ExecutionMode": "GUI",
  "LockPane": true,
  "Description": "設定をエディタで編集し、保存まで待機"
}
```

```json
{
  "Name": "Edit with Vim",
  "Command": "vim \"$P\\$F\"",
  "ExecutionMode": "TUI",
  "Description": "ターミナル Vim で編集（自動ロック）"
}
```

```json
{
  "Name": "Jump using fzf",
  "Command": "powershell -command \"Get-ChildItem -Directory | ForEach-Object {$_.FullName} | fzf.exe\"",
  "ExecutionMode": "TUI",
  "PipeToAction": "JumpToPath",
  "Description": "fzf で対話的にディレクトリ選択・ジャンプ"
}
```

#### **ペイン ロックが必要な理由（3 つの背景）**

1. **ターミナル所有権（共有コンソール）**
   - 外部プロセスが rwf と同じターミナルを共有する
   - プロセスが対話的な場合（fzf, vim）、入出力を巡って競合
   - 解決策: ペイン ロック → rwf の UI 描画を中止 → プロセスにターミナルを譲渡

2. **出力キャプチャ（PipeToAction）**
   - コマンド出力を内部アクション（JumpToPath, ExecuteFile）にパイプするとき、完全な stdout バッファを待つ必要がある
   - プロセス終了まで待たないと出力を取得できない

3. **状態一貫性（Layer 1 リフレッシュ）**
   - コマンドが filesystem を変更した場合（git checkout, unzip など）、即座にペインをリフレッシュ必要
   - ロックにより、コマンド完了直後の同期リフレッシュを保証

#### **ExecutionMode: GUI（ノンブロッキング）**

**デフォルト動作（LockPane: false）:**

```
ユーザーが GUI コマンド実行
  ↓
JobManager がコマンドをバックグラウンド ジョブで spawn
  ↓
rwf が応答可能（ペイン切り替え、他機能利用可能）
  ↓
コマンド完了
  ↓
Transition::Refresh シグナル送信
  ↓
ペイン自動リフレッシュ（Layer 1）
```

**用途**: 高速操作（Notepad 起動、WinMerge 起動、Explorer 開く）
- rwf の操作中にコマンド実行される必要がない
- コマンドがファイル状態と無関係
- PipeToAction 不要

**ペイン ロック付き（LockPane: true）:**

```
ユーザーが GUI コマンド実行
  ↓
ペイン ロック状態になる：
  - UI 色が 30% 暗くなる（読可、しかし明らかにロック中）
  - メッセージ表示: "Command running... (ESC to cancel)"
  - ペインへの入力が無効化される
  ↓
JobManager がコマンドを spawn
  ↓
JobManager.wait() このジョブ完了まで待機（UI 全体ではなく）
  ↓
ユーザーができる操作:
  - 他のペインにフォーカス移動（rwf はまだ使用可能）
  - ロック中ペインで ESC を押す → プロセスに graceful shutdown シグナル送信
  ↓
コマンド完了
  ↓
ペイン ロック解除
  ↓
Transition::Refresh シグナル送信
  ↓
ペイン自動リフレッシュ
```

**用途**: rwf がコマンド完了を待つ必要がある場合
- 設定エディタ: ユーザーが保存するまで設定リロード待機
- 出力パイプ コマンド（TUI モードではない）: stdout キャプチャ必要
- ファイル状態変更: リフレッシュがコマンド完了に依存

**例:**
```
ユーザー → Z キー → "Edit Config" → EditConfigFile { filename: "config.json" }
  ↓
config.json が notepad で開く
ペイン がロック（"Command running... (ESC to cancel)" と表示）
ユーザーが notepad で編集・保存
notepad を閉じる
  ↓
rwf がプロセス終了を検知
ペイン アンロック
rwf が設定をリロード
```

#### **ExecutionMode: TUI（ターミナル制御）**

**自動ペイン ロック動作:**

```
ユーザーが TUI コマンド実行
  ↓
ペイン は自動的にロック（TUI は常にロック必須）
  ↓
rwf の TUI 描画を中止
  ↓
ターミナル制御を外部プロセスに譲渡
  ↓
ユーザーがコマンドと対話（vim, fzf, git-interactive）
  ↓
コマンドが終了シグナル送信
  ↓
rwf がプロセス終了を検知
  ↓
rwf の TUI 描画を再開
  ↓
ペイン アンロック
  ↓
コマンド出力をキャプチャ（PipeToAction が設定されている場合）
  ↓
Transition::Refresh シグナル送信
  ↓
ペイン自動リフレッシュ
```

**用途**: ターミナル制御が必要な対話的コマンド
- vim, nano, emacs（エディタ）
- fzf, ripgrep-interactive（セレクタ）
- git log --interactive, git add -i（Git ツール）

**例:**
```
ユーザー → E キー → "Edit with Vim" (ExecutionMode: TUI)
  ↓
rwf が TUI 描画中止 → ターミナルを vim に譲渡
  ↓
vim が起動、ユーザーが編集・保存
  ↓
:q で vim 終了
  ↓
rwf がプロセス終了を検知、TUI 描画再開
  ↓
ファイルが更新されたことを検知
  ↓
ペイン自動リフレッシュ（更新されたファイルが表示される）
```

## 7. マクロ展開 完全リファレンス

### **マクロ展開システム 完全リファレンス**

#### **ペイン パス**

| マクロ | 説明 | 例 |
|--------|------|-----|
| `$P` または `%P%` | アクティブペイン ディレクトリ | `C:\Users\user\Downloads` |
| `$O` または `%O%` | 反対ペイン ディレクトリ | `C:\Users\user\Documents` |
| `$L` または `%L%` | 左ペイン ディレクトリ | `C:\Users\user\Downloads` |
| `$R` または `%R%` | 右ペイン ディレクトリ | `C:\Users\user\Documents` |

#### **ファイル/カーソル**

| マクロ | 説明 | 例 |
|--------|------|-----|
| `$F` または `%F%` | カーソル ファイル名（拡張子付き） | `report.pdf` |
| `$W` または `%W%` | カーソル ファイル名（拡張子なし） | `report` |
| `$E` または `%E%` | カーソル 拡張子 | `pdf` |
| `$#` または `%#%` | ペイン内ファイル数 | `42` |

#### **マーク済み/全ファイル**

| マクロ | 説明 | 出力 |
|--------|------|------|
| `$M` または `%M%` | マーク済みファイル（shell-quoted） | `"file 1.txt" "file 2.pdf"` |
| `$*` または `%*%` | ペイン内全ファイル（shell-quoted） | `"README.md" "src"` |

#### **ホーム ディレクトリ**

| マクロ | 説明 | 例 |
|--------|------|-----|
| `$~` | ホーム ディレクトリ | `C:\Users\user` または `/home/user` |

#### **ユーザー入力**

| マクロ | 動作 |
|--------|------|
| `$I` | ダイアログでユーザー入力を促す、入力テキストに置換 |

#### **環境変数展開パターン**（拡張順: 1→4）

**1. PowerShell スタイル（Windows）**
```
$env:VARNAME  →  環境変数から値を取得
```
例:
- `$env:USERPROFILE` → `C:\Users\user`
- `$env:APPDATA` → `C:\Users\user\AppData\Roaming`
- `$env:TEMP` → `C:\Users\user\AppData\Local\Temp`

**2. Windows バッチ スタイル**
```
%VARNAME%  →  環境変数から値を取得
```
例:
- `%USERPROFILE%` → `C:\Users\user`
- `%APPDATA%` → `C:\Users\user\AppData\Roaming`

**3. Unix ブラケット スタイル**
```
${VARNAME}  →  環境変数から値を取得
```
例:
- `${HOME}` → `/home/user`
- `${LOG_DIR}` → `/var/log`

**4. Unix シンプル スタイル**
```
$VARNAME  →  環境変数から値を取得
```
例:
- `$HOME` → `/home/user`
- `$PATH` → `/usr/bin:/bin:...`

**展開順序**: `$env:VAR` → `%VAR%` → `${VAR}` → `$VAR`（競合を避けるため）

#### **フル コマンド例**

**例 1: タイムスタンプ付きアーカイブ**
```json
{
  "Name": "Archive marked files",
  "Command": "tar -czf \"$~/$#_files_$(date +%s).tar.gz\" $M",
  "Shell": "/bin/bash",
  "ExecutionMode": "GUI"
}
```
展開結果: `tar -czf "/home/user/5_files_1623456789.tar.gz" "file1" "file2" "file3" "file4" "file5"`

**例 2: クロスプラットフォーム設定エディタ**
```json
{
  "Name": "Edit config",
  "Command": "notepad \"$env:APPDATA\\rwf\\config.json\"",
  "Shell": "cmd.exe",
  "ExecutionMode": "GUI",
  "LockPane": true
}
```
展開結果: `notepad "C:\Users\user\AppData\Roaming\rwf\config.json"`

**例 3: ユーザー入力付きコピー**
```json
{
  "Name": "Copy to custom location",
  "Command": "copy \"$P\\$F\" \"$I\" Destination folder\"",
  "Shell": "cmd.exe",
  "ExecutionMode": "GUI"
}
```
動作: ユーザーに `Destination folder` をプロンプト → 例: `C:\Backup\` → 
展開結果: `copy "C:\Users\user\Downloads\myfile.txt" "C:\Backup\"`

**例 4: fzf での対話的ジャンプ**
```json
{
  "Name": "Jump with fzf",
  "Command": "powershell -command \"Get-ChildItem -Directory | ForEach-Object {$_.FullName} | fzf.exe\"",
  "Shell": "powershell.exe",
  "ExecutionMode": "TUI",
  "PipeToAction": "JumpToPath"
}
```
動作: fzf が起動 → ユーザーがディレクトリ選択 → 出力が JumpToPath にパイプ → rwf がそのパスにナビゲート

```
└────────────────┬────────────────────────────────────┘
                 ↓
┌─────────────────────────────────────────────────────┐

```
