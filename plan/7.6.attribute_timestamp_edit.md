# Phase 7.11 — 属性/タイムスタンプ変更

**作成日**: 2026-07-29
**状態**: 実装完了（2026-07-30。§2〜4のダイアログ設計・データモデル・バックエンド/Jobどおりに実装、全テストグリーン）
**対象**: ファイル属性（Windows: ReadOnly/Hidden/System/Archive、Unix: パーミッション）とタイムスタンプ（modified/accessed、Windowsのみcreatedも）の編集。[7.6 Undo/Redo](7.6.transactional_rollback.md) の前提操作。

---

## 1. 背景・位置づけ

7.6（Undo/Redo、Operation Report）は Undo対象表（[7.6.operation_report_ui.md](7.6.operation_report_ui.md)）で
Attribute Change / Timestamp Change を `○` として要求しているが、現状 `JobKind` は一切実装されていない。
`7.6.transactional_rollback.md` §8 は、in-place 型操作（旧値保持が必要）のスキーマを 7.6 着手前に
固めておく必要があると指摘しており、本ドキュメントはその前提操作の一つを具体化する。

参照実装（TWF, `specs/twf/`）には属性/タイムスタンプの編集UIは存在しない（`FilePropertiesDialog` は
読み取り専用）。本機能は rwf 独自のUXとして設計する。

## 2. ダイアログ設計

### 起動キー

`Ctrl+a`。既存の `Ctrl+` 系バインド（`Ctrl+n`/`Ctrl+u`/`Ctrl+t`/`Ctrl+w`/`Ctrl+b`/`Ctrl+j`/`Ctrl+k`/`Ctrl+d`/`Ctrl+f`、
[default_keybindings.json](../rwf-lib/resources/default_keybindings.json)）と表記を揃え、FAR Manager 等の
双璧型ファイラーで定着している「属性変更 = Ctrl+A」慣習とも一致する（現状未使用）。マーク済みファイルが
あればそれら全てが対象、無ければカーソル位置の1件が対象。

### 専用ダイアログ、Renameとは統合しない

フィールド数・チェックボックス操作が単一テキスト入力と質的に異なるため。`SimpleRenameDialog`
（`rwf-lib/src/model/dialog/simple_rename.rs`）のTab循環フォーカス + `DialogUiState` パターン、
`file_info.rs` のラベル/値の行レイアウトを流用する。

### 1ダイアログ、条件付きフィールド

属性とタイムスタンプを1画面で扱う（2画面に分けない）。`#[cfg(windows)]`/`#[cfg(unix)]` で表示内容を
切替える点は `local.rs` の既存の隠し属性判定（`local.rs:79-86`）と同じ流儀。

- **Windows**: ReadOnly / Hidden / System / Archive のチェックボックス
- **Unix**: 8進数（例: `755`）の直接入力を主入力としつつ、rwxrwxrwx表示をリアルタイム連動させる
  権限フィールド。個別ビットをカーソル+Spaceでトグルする操作もでき、その場合も8進数表示側が追従する。
  どちらの入力方法で編集しても最終的に同じ `mode: Option<u32>` に収束する（シンボリック表示「または」
  8進数入力の二択ではなく、両方が常に同じ値を指す1つのフィールド）。owner/group は非root運用が大半の
  ため v1 では編集対象外（表示のみ、または省略）。

### タイムスタンプ欄はOS依存で数が変わる

- **Windows**: modified/accessed/created の3欄すべてを編集可能として表示（NTFSは `SetFileTime` で
  3つとも設定できる）。
- **Unix**: modified/accessed の2欄のみを表示し、created（birthtime）欄自体を出さない（設定手段が
  標準的に無く、取得すら困難なため）。

### touch機能はこのダイアログに折り込む

各タイムスタンプ欄に `Now` ラベルのキー（例: `t`）を割り当て、`SystemTime::now()` をその場でスタンプ
する（UIの他ラベルは英語表記のため `Now` で統一）。単独のtouch機能を別途作らない。

### マーク（複数選択）ファイルの一括編集（v1スコープ）

`PaneModel::marked_entries()`（`rwf-lib/src/model/pane.rs:67`）を使用。ダイアログを開いた時点で
全対象の値を比較し、一致していれば初期値として表示、不一致なら混在状態インジケータ（チェックボックス
は `[-]` 相当のtri-state、タイムスタンプ欄は空欄/`<mixed>`）で表示する。ユーザーが明示的に触った
項目だけを `Some(値)` として全対象に適用し、触らなかった項目は `None`（変更なし）として各ファイルの
既存値を温存する。

## 3. データモデル

```rust
// rwf-lib/src/model/attrs.rs (新規)
pub struct AttributeChange {
    #[cfg(windows)] pub readonly: Option<bool>,
    pub hidden: Option<bool>,
    pub system: Option<bool>,
    pub archive: Option<bool>,
    #[cfg(unix)] pub mode: Option<u32>,
}

pub struct TimestampChange {
    pub modified: Option<SystemTime>,
    pub accessed: Option<SystemTime>,
    #[cfg(windows)]
    pub created: Option<SystemTime>, // NTFSはSetFileTimeで作成日時も設定可能
    // Unixはbirthtimeの標準的なsetterが無い（取得自体も困難）ため、フィールド自体を持たない。
    // ダイアログ側もUnixではcreated欄を非表示にする（グレーアウトではなく非表示）。
}

pub struct FileOpOutcome<T> {
    pub target: Location,
    pub old: Option<T>,
    pub new: T,
    pub result: Result<(), String>,
}
```

`FileOpOutcome<T>` は7.6のUndoが実際に消費するのは後だが、今のうちに旧値を保持する形で実行結果を
積む（fail-fastにせず、対象ファイルごとにループしてVecへ蓄積 — `7.6.transactional_rollback.md` §8の
ガイドライン通り）。旧値は `FileInfoDialog` と同様、ダイアログを開いた時点で対象ファイルのメタデータを
都度取得して得る（`FileEntry` 側の拡張は不要）。

## 4. バックエンド・Job

`FilesystemBackend` トレイト（`rwf-lib/src/backend.rs`）に新規メソッドを追加、`local.rs` にのみ実装
（`Location::Local` 以外はbail、既存の変更系メソッドと同じ）:

- `set_attributes(&self, location, attrs: &AttributeChange, cancel_token) -> Result<AttributeChange>`
  （戻り値は変更前の値）
- `set_timestamps(&self, location, times: &TimestampChange, cancel_token) -> Result<TimestampChange>`

プラットフォーム実装:
- Windows属性: `std::os::windows::fs::MetadataExt::file_attributes()` 読み取り + `FILE_ATTRIBUTE_*`
  ビット操作 + `SetFileAttributesW`
- Unix権限: `std::os::unix::fs::PermissionsExt`
- タイムスタンプ: `filetime` クレート（未導入、`rwf-lib/Cargo.toml` に追加要）。`set_file_mtime`/
  `set_file_atime` が可搬。Windows作成日時は `SetFileTime` 系API

`JobKind`（`rwf-lib/src/job.rs:97`）に追加:
```rust
ChangeAttributes { targets: Vec<Location>, attrs: AttributeChange },
ChangeTimestamps { targets: Vec<Location>, times: TimestampChange },
```

`job_executor.rs` に `execute_change_attributes`/`execute_change_timestamps` を追加。Mkdir/Rename/
Delete と同じdispatchパターン（`job_executor.rs:62-64`）に従う。対象ごとにループし
`Vec<FileOpOutcome<T>>` へ結果を蓄積する（fail-fastにしない）。
