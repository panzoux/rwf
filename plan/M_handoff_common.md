# Phase M4–M7 引き継ぎ共通規約

作成: 2026-07-05(Fable 5 退役 2026-07-07 に伴う既存モデルへの引き継ぎ)。
各フェーズの詳細は `M4_handoff.md` / `M5_handoff.md` / `M6_handoff.md` / `M7_handoff.md`。
背景と設計判断の根拠は `quality_overhaul.md`。**設計判断は全て確定済み — 実行セッションで再設計しない。**

## モデル使用原則(必要十分・使用量最小)

| 役割 | モデル | 理由 |
|---|---|---|
| オーケストレータ(全セッション) | **sonnet** | 設計は本ファイル群で確定済みのため opus 不要。判断は「指示の適用」のみ |
| 機械的一括作業(バリアント畳み込み・rustdoc 下書き・スモークテスト量産) | **haiku**(general-purpose subagent) | テンプレート必須添付。下記の途中死対策を厳守 |
| 棚卸し・調査(clone 候補抽出・関数所属マップ) | **haiku**(Explore subagent) | 読み取り専用なので事故リスクなし |
| **opus** | **原則使わない** | 使うのは「本ファイル群の指示と実コードが矛盾して先へ進めない」場合の単発判断のみ。使ったら判断結果を該当 handoff ファイルに追記して即 sonnet に戻す |

## セッション分割・途中死防止(5 時間制限対策)

1. **1 セッション = handoff ファイルの 1 セッション欄**。欲張って次セッション分に着手しない。
2. **着地単位で必ずコミット**(着地単位は各フェーズファイルに定義)。「大きな変更を貯めてから一括コミット」は禁止。
   セッションが途中死しても、コミット済み部分は失われず、未コミット部分は `git checkout -- .` で捨てて再開できる。
3. セッション終了時(または残量に不安が出た時点)に、**進捗チェックボックスを handoff ファイルに記入してコミット**してから終了する。次セッションはチェックボックスの続きから開始。
4. subagent 分配は**カナリア方式**: まず 1 エージェントに最小単位を実行させ、成果 diff を監査してから残りを投入。

## 並列 haiku subagent 運用(M2/M3 の実事故に基づく必須ルール)

- **指示に必ず含める**: 「1 単位(1 ファイル / 1 バリアント)ずつ一貫状態で完結させる。import と呼び出し側を同時に更新し、次の単位に移る前に grep で旧参照の残存ゼロを確認」。途中死時に半端編集を残さないため。
- **エージェントに cargo 実行禁止**を明示(共有ビルドディレクトリで他エージェントの中間状態を見て誤爆する)。検証はオーケストレータに集約。
- **diff 監査必須**: エージェント完了ごとにオーケストレータが `git diff` を監査。特に削除行の非デフォルト値(`Some(..)`, `true`, 数値リテラル)が追加行に対応を持つか突合する。haiku は非デフォルト値を黙って落とすことがある。
- **共有ファイルに並列書き込みさせない**。並列可否は各フェーズファイルに明記してある(M4 は共有ファイル集中のため**並列禁止・直列バッチ**)。
- 見本テンプレート(実コード)を必ず添付。口頭説明だけで任せない。

## 環境注意(毎セッション有効)

- 改行は **LF**(autocrlf=false)。PowerShell `Set-Content`/`Out-File` は CRLF 化するので**ソース編集は Edit ツールのみ**。コミット前に `git diff --numstat` で全行書き換え(=改行事故)がないか確認。
- テストは常に `--test-threads=1`。rwf-lib フルは約 40 分 — **バックグラウンド実行し、待ち時間にドキュメント系タスクを進める**。
- 検証一式: `cargo fmt --all -- --check` / `cargo clippy --all-targets -- -D warnings` /
  `cargo test -p rwf -- --test-threads=1` / `cargo test -p rwf-lib -- --test-threads=1`
- リファクタでメソッドを消した/改名したら `cargo test -p rwf --no-run` も実行(rwf-bin テストの stale 参照でワークスペースが割れた前歴あり)。
- スナップショット(insta)が差分を出したら、それは**実装ミス**(全 M フェーズは挙動保存)。`cargo insta review` で accept しない。唯一の例外は M7 の archive.rs TODO 修正。
