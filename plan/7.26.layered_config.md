# 7.26 設定の多層化（組み込み既定 + ユーザー上書き）

**状態**: `[x]` 実装・検証済み（2026-09-19 起票・完了、2026-09-20 実機 TUI 目視確認済み）
**由来**: 2026-09-19、`custom_functions.json` を退避したら custom function が 0 件になり、
既定キーバインド（F6 クリップメニュー、`z` 設定メニュー、F4/Shift+F4 fzf）が名前で指す先を失って無反応になった。
新規インストールでも毎回同じことが起きる。

## 1. 目的

すべての設定ファイルを `keybindings.json` と同じ振る舞いにする: **組み込み既定は常に読み込み、ユーザーファイルは
上書き・追加だけを書く**。新規インストールでそのまま動き、ユーザーは変えたい分だけ書けばよい。

## 2. 現状（2026-09-19 調査）

| ファイル | ユーザーファイルが無いとき | 場所 |
|---|---|---|
| keybindings.json | 既定 + ユーザーを上にマージ | `KeyBindings::load_from_file`（`input/mod.rs:170`） |
| file_type_map.json | 埋め込み既定にフォールバック（ある時は丸ごと置換） | `config.rs:1329` |
| custom_functions.json | 空リスト | `load_custom_functions`（`model/dialog/mod.rs:2368`） |
| menu_*.json | 空メニュー + ログ警告のみ（`DEFAULT_MENU_CLIP`/`CONFIG` は埋め込み済みなのに） | `resolve_menu_files`（`mod.rs:2758`） |
| extension_associations.json | 何も無し、"Skipped" | `config.rs:1281` |

- 読み込みは **起動**（`AppState::new` + `main.rs` の config/keybindings）と **リロード**（`Transition::ReloadConfig`
  + `app.rs` の keybindings 2 箇所）でほぼ同じコードが重複していた → 1 関数に集約する。
- keybindings で任意の文字列は custom function 名になるため、**キーを外す手段が無い**。

## 3. 仕様

### 3.1 マージ規則

| ファイル | マージキー | ユーザーエントリの効果 |
|---|---|---|
| config.json | フィールド名 | そのフィールドを上書き（既存どおり） |
| keybindings.json | モード毎のキー | 再割り当て（既存どおり）。`null` / `"None"` で既定を外す |
| custom_functions.json | `Name` | 同名は既定を置換（位置は既定の位置のまま）、新名は末尾に追加 |
| menu_*.json | ファイル名 | ユーザーファイルがあれば組み込みメニューを丸ごと置換、無ければ組み込み |
| extension_associations.json | `Extension` + `FileType` | ユーザーを先に、既定を後に。同じキーの既定は隠れる |
| file_type_map.json | `Extension` | ユーザーを先に、既定を後に。同じキーの既定は隠れる |

- 削除: custom functions と 2 つの関連付けファイルは同名/同キーのエントリに `"Disabled": true`。
  `Disabled` のエントリは型付きパースの**前に** JSON 値の段階で取り除く（`Command` 等の必須項目を書かずに済む）。
- 関連付けで「同じキーの既定を隠す」のは判断: 関連付けは一致した全件を Open With ピッカーに出すので、
  隠さないと上書きのたびにピッカーが出るようになる。

### 3.2 モード切替

- `config.json` の `"UseBuiltInDefaults": true|false`（既定 true）。false = ユーザーファイルが**あれば**それが組み込みを置き換える
  （削除すれば消える旧挙動）。ファイルが無いものは組み込みを使う。
- CLI `--no-default-config`: この実行だけ置換モード。
- CLI `--no-user-config`: `%APPDATA%\rwf\` の設定ファイル（config.json, keybindings.json, custom_functions.json,
  menu_*.json, 関連付け 2 種）を無視して組み込みだけで動く（不具合再現用）。セッション・登録フォルダは対象外。
- 2 つのフラグは同時指定不可。対象はリスト型ファイルのみ（config.json は常にコード既定がある）。リロードも同じモード。
- モードは設定読み込みレポートと診断バンドルの `config_effective.json` に出す。stdout には書かない（IMPLICIT_CONTRACTS §1）。

### 3.3 エクスポート

`--export-config-files` は従来どおり既定の全文を書く。
- 全文エクスポートはそのまま有効（全エントリが同一内容で既定を上書き → 挙動不変）。
- エクスポートしたファイルからエントリを**消しても**既定が埋めるので消えない → `"Disabled": true` が必要。
  書式が許すファイル（custom_functions, keybindings, menu_*）の `_comment` と USER_GUIDE に明記。
  配列だけのファイル（file_type_map, extension_associations）はコメントを持てないので、エクスポート時の出力と USER_GUIDE で説明。

### 3.4 見える化

- 設定読み込みレポートに層の内訳: 例 `custom_functions.json (3 user entries over 21 built-in)`。
- 関数一覧（Custom Functions ダイアログ）とヘルプの Custom Functions タブで built-in / user を表示。
- `config_effective.json` にモードと解決済みの custom functions を追加記録。

## 7. 追補: `default_config.json`（2026-09-19）

config.json の既定は従来コード（`AppConfig::default()` + 各フィールドの serde default）にしか無く、
エクスポート時にシリアライズしていた。他の `default_*.json` と並べて読めるよう
`rwf-lib/resources/default_config.json` を追加し、エクスポートはこのファイルをそのまま書く。
正はコードのまま。`config_contracts.rs` の `default_config_json_matches_app_config_default` がずれを検出し、
`RWF_REGENERATE_DEFAULT_CONFIG=1 cargo test -p rwf --test config_contracts` で再生成する。
